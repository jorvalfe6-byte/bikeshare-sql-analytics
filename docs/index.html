What 6 million bike trips say about a city

I took a year of public trip data from Capital Bikeshare, Washington D.C.'s bike-share system, modelled it in PostgreSQL and asked the questions an operator would ask: when does demand peak, who rides, which stations run out of bikes, and how fast are electric bikes taking over.

How it's built

The whole process rebuilds from scratch with one command (./scripts/load.sh).

  1. StagingThe 12 monthly CSV files load as plain text with \copy, so a odd value never stops the load.
  2. CoreTyped model with primary keys, foreign keys and CHECKs. 141 trips that cross midnight at a month end come in two files; one copy is kept and the count is logged.
  3. Checks13 checks compare counts with the published files. The load fails if any says REVIEW.
  4. MartA materialized view of every trip with its validity. Excluded trips keep the reason: nothing is dropped silently.
  5. AnalysisWindow functions, percentiles, ranking, calendar tables and a rebalancing model over six million rows.
  6. PublicationOnly aggregates leave the database, as one small JSON that this page draws without external libraries.

Data: Capital Bikeshare system data, used under the Capital Bikeshare Data License Agreement. This page publishes aggregates only.

Times are local to Washington D.C. (the source has no time zone). A valid trip is physically plausible: it ends after it starts, lasts at most 24 h and is not a sub-minute return to the same dock.
